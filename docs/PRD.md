# GAME FORGE PRD

> 상태: Discovery 초안 · 저장소 기반 가정 포함  
> 작성일: 2026-08-04  
> 제품 단계: 성숙한 프로토타입의 MVP 안정화

## 1. Overview

### 비전

게임 제작 경험이 적은 창작자도 자신의 아이디어를 잃지 않고, 구현 가능한 게임 기획과 검증 가능한 개발 명세를 만들 수 있게 한다.

### 문제

- 아이디어를 플레이어 행동, 규칙, 상태 변화와 승패 조건으로 바꾸기 어렵다.
- 스토리와 게임 시스템이 분리되어 “설명은 있지만 플레이는 없는” 기획이 되기 쉽다.
- 코딩 에이전트에 전달할 요구사항·완료 조건·테스트 기준을 직접 쓰기 어렵다.
- 긴 AI 결과를 사용자가 검토하고 수정하기 어렵다.

### 제품 정의

GAME FORGE는 다음 흐름을 제공하는 한국어 AI 게임 기획 워크숍이다.

`아이디어 → 플레이 가능한 스토리 → 편집 가능한 온톨로지 → 게임 기획안/비주얼 보드 → Build Goals → Build Spec`

현재 제품의 종착점은 게임 코드 자체가 아니라 **Codex·Claude 등 코딩 에이전트가 실행할 수 있는 Build Spec**이다.

## 2. Target Users

### 주 사용자 — 인디 메이커·초기 기획자

- 게임 아이디어는 있지만 시스템 설계나 기획서 작성 경험이 적다.
- 코딩 에이전트로 작은 브라우저 게임을 만들고 싶다.
- 성공 기준: 30분 내 자신의 의도가 반영된 Build Spec을 확보한다.

### 보조 사용자 — 워크숍 진행자·교육자

- 참가자별 프로젝트를 분리하고 결과를 파일로 회수한다.
- 제한된 시간과 AI 비용 안에서 공통 품질 기준을 적용한다.

### 후속 사용자 — 게임 구현 개발자

- 추가 기획 인터뷰 없이 구현을 시작할 명확한 작업·수용 기준·테스트 계약이 필요하다.

## 3. Value & Success Metrics

### 핵심 가치

- **아이디어 우선**: 장르 성공 패턴은 참고하되 고유 아이디어를 덮어쓰지 않는다.
- **플레이 가능성**: 모든 서사 요소를 플레이어 행동과 상태 변화에 연결한다.
- **사용자 통제**: 생성 결과를 직접 편집하고 자연어 피드백으로 재생성한다.
- **구현 가능성**: Build Spec에 작업, 수용 기준, 밸런스, 테스트와 완료 계약을 포함한다.

### KPI 초안

| 지표 | MVP 목표 |
| --- | --- |
| 아이디어 입력 → Build Spec 내보내기 완주율 | 50% 이상 |
| story/concept/goals 단계별 생성 성공률 | 각 90% 이상 |
| 새로고침 후 프로젝트 복원 성공률 | 99% 이상 |
| “추가 기획 없이 구현 시작 가능” 평가 | 5점 만점 4.0 이상 |
| 생성 요청 p95 | 5분 이하, 15분 강제 종료 |
| 비밀값 노출·데이터 혼합·유효하지 않은 관계 | 0건 |

## 4. Scope

### P0 — 기존 핵심 기능 유지

1. 장르 프리셋 8종과 커스텀 장르
2. 아이디어, 스토리 규모, 2D/3D 표현 방식 선택
3. Bedrock 기반 구조화 스토리 생성
4. 막·코어 루프·온톨로지 노드/관계 직접 편집과 그래프 보기
5. 자연어 대화로 스토리 수정
6. 게임 기획안 생성·편집·피드백 재생성
7. 캐릭터·환경 이미지 개별/일괄 생성과 PNG 다운로드
8. 검증·아트·밸런스·재미 반복·완료 계약을 포함한 Build Goals
9. 다중 프로젝트 자동 저장·전환
10. 프로젝트 JSON, Build Spec Markdown, 실행 프롬프트 내보내기
11. 생성 취소, 타임아웃, 중복 요청 방지와 오류 안내

### P0 — 다음 개발 우선순위

1. **런타임 검증**: 클라이언트·API 입력과 Bedrock 응답을 스키마로 검증한다.
2. **산출물 일관성**: story 변경 시 concept/goals를 무효화하고 오래된 결과 사용을 막는다.
3. **복원 안전성**: 프로젝트 스키마 버전, 저장 데이터 검증, 안전한 마이그레이션을 추가한다.
4. **오류 회복**: 인증·타임아웃·제공자·검증 오류를 구분하고 이전 유효 결과를 보존한다.
5. **테스트**: 생성 상태 전이, 저장/복원, 내보내기와 핵심 퍼널을 자동화한다.
6. **접근성·모바일**: 키보드 포커스, 상태 알림, 반응형 편집 흐름을 보완한다.

### P1

- 프로젝트 JSON 가져오기와 완전한 백업/복구
- 생성 이미지 영속화 또는 묶음 다운로드
- 단계별 변경 이력, 이전 생성본 비교와 되돌리기
- 토큰·비용 예상치와 사용 한도 표시
- 코딩 에이전트 handoff 패키지 자동 구성

### P2 — 사용자 확인 후 별도 범위

- 계정·초대·클라우드 프로젝트 저장과 워크숍 관리
- Game Ontology v2 revision/branch/approval/ownership
- S3/DynamoDB/Neptune 기반 canonical graph와 GraphRAG
- StoryForge, Local Companion, Unity 6 동기화
- GAME FORGE 내부의 실제 게임 코드 생성·빌드·호스팅
- 실시간 공동 편집과 결제

## 5. Functional Requirements

### FR-01 프로젝트 관리 (P0)

- 여러 프로젝트를 생성·저장·전환하고 마지막 작업을 새로고침 후 복원한다.
- 자동 저장은 디바운스하며 손상된 데이터가 앱 전체를 중단시키지 않아야 한다.
- 생성 중 프로젝트 전환으로 데이터가 섞이지 않아야 한다.

### FR-02 아이디어와 스토리 (P0)

- 사용자는 장르, 아이디어, 막 수, 2D/3D를 선택해 스토리를 생성한다.
- 생성 결과는 제목, 로그라인, 역할, 세계, 갈등, 코어 루프, 막별 행동/상태 변화, 노드, 관계를 포함한다.
- 모든 관계는 존재하는 노드를 참조하고 노드 ID는 중복되지 않아야 한다.
- 사용자는 모든 필드를 편집하고 자연어 지시로 수정할 수 있다.

### FR-03 기획안과 이미지 (P0)

- 스토리를 시점, 세션 흐름, 메커닉, 조작, 성장, 실패/회복, 캐릭터, 환경, 오디오를 포함한 기획안으로 만든다.
- 사용자는 직접 편집하거나 피드백을 반영해 다시 생성한다.
- 캐릭터와 환경 프롬프트로 이미지를 생성·미리보기·재생성·다운로드한다.
- 한 이미지 실패가 다른 이미지나 프로젝트 데이터를 삭제하지 않아야 한다.

### FR-04 Build Goals와 Spec (P0)

- 확정 기획을 검증, 최종 목표, 아트, 이미지, 밸런스, 재미 반복, 완료 계약, 구현 Goal로 변환한다.
- Goal마다 목적, 작업, 수용 기준과 의존성이 있어야 한다.
- Gameplay, Story, Controls, Character, World, UI, Audio, Persistence, QA, Packaging을 다룬다.
- 빈 필드, TODO, placeholder, 근거 없는 완료 선언을 허용하지 않는다.
- 사용자는 JSON/Markdown 다운로드와 클립보드 복사를 할 수 있다.

### FR-05 생성 상태와 오류 회복 (P0)

- 동시에 하나의 텍스트 생성만 허용하고 진행 단계·경과 시간·취소를 제공한다.
- 텍스트는 15분, 이미지는 5분 후 타임아웃한다.
- 실패 시 입력과 마지막 유효 결과를 유지하고 재시도할 수 있어야 한다.
- 인증, 잘못된 입력, 타임아웃, 모델 오류를 구분해 안내한다.

## 6. Non-Functional Requirements

### 성능·신뢰성

- 편집 입력은 100ms 이내 화면에 반영한다.
- 자동 저장은 부분 객체를 쓰지 않고 스키마 버전을 기록한다.
- `story → concept → goals` 의존성을 강제한다.
- 상위 결과 변경 시 하위 결과를 무효화하거나 “오래됨”으로 표시한다.

### 보안

- Bedrock Key는 `.env.local`, 실행 역할 또는 비밀 저장소에서만 읽는다.
- 비밀값을 클라이언트 번들, localStorage, 로그, JSON/Markdown에 포함하지 않는다.
- API 요청 크기·문자열 길이·허용 모델을 서버에서 제한한다.
- 호스팅 전 인증, 사용자 격리, Origin/CSRF, 비용 한도와 감사 로그를 완료한다.

### 접근성·호환성

- 최신 Chrome, Firefox, Safari와 모바일 Safari/Chrome을 목표로 한다.
- 모든 핵심 조작은 키보드로 가능하고 포커스가 보여야 한다.
- 로딩·성공·오류 상태는 색상 외 텍스트와 보조 기술 알림을 제공한다.

### 품질 게이트

- `npm run lint`, 프로덕션 빌드, 핵심 API 테스트를 통과한다.
- 장르 선택부터 Build Spec 다운로드까지 브라우저 E2E를 통과한다.
- 콘솔 오류, 깨진 자원, 비밀값 노출, 프로젝트 혼합이 0건이어야 한다.

## 7. Technical Constraints

- Next.js 16, React 19, TypeScript 5.9, Node.js 22.13 이상
- 텍스트 생성: Amazon Bedrock Converse, 기본 Claude Sonnet 4.6
- 이미지 생성: Amazon Bedrock Stability, 기본 리전 `us-west-2`
- 현재 저장: localStorage; 현재 산출물: JSON, Markdown, PNG
- UI 기본 언어: 한국어
- 샘플 게임은 Build Spec 실현 사례이며 GAME FORGE 핵심 기능과 배포 상태를 대신하지 않는다.
- `GAME_ONTOLOGY_V2.md`와 Unity/클라우드 기반 코드는 향후 플랫폼 자산이며 현재 `/game-builder` 데이터 계약과 분리한다.

## 8. Assumptions

개발을 멈추지 않기 위해 다음을 임시 확정한다.

1. MVP 종착점은 Build Spec 내보내기다.
2. 첫 대상은 단일 사용자 로컬/BYOK 워크숍이다.
3. 사용자가 Bedrock Key를 서버 환경에 직접 설정한다.
4. 브라우저 저장과 JSON 내보내기를 현재 백업 수단으로 사용한다.
5. 한국어 단일 언어와 브라우저 게임용 명세를 우선한다.
6. 클라우드·Unity·실제 코드 생성은 P2다.

## 9. Open Questions — 사용자 확인 필요

1. Build Spec 이후 실제 게임 생성·배포까지 GAME FORGE가 담당해야 하는가?
2. 개인 로컬 도구와 초대형 온라인 워크숍 중 무엇이 우선인가?
3. 로그인 기반 클라우드 저장이 P0인가?
4. 생성 게임의 기본 대상은 브라우저인가, Unity인가, 둘 다인가?
5. BYOK만 지원할 것인가, 운영자 부담형 AI 사용도 제공할 것인가?
6. 검증 점수가 낮은 기획의 내보내기를 경고할 것인가 차단할 것인가?
7. 현재 export만 있는 JSON의 import/복원을 P0로 올릴 것인가?
